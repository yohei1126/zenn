## 概要

第1部で構造的ボトルネックを、第2部でグラフ・共用埋め込み・多目的最適化の理論を置いた。第3部では、三者の知見が統合されたとき設計・品証・製造の働き方がどう変わるかを、**システムアーキテクチャとUI/UX**として描く。

キーワードは次の三つである。

1. 設計・品証・製造データを非同期で吸い上げる統合パイプライン
2. CAD操作に連動するプッシュ型（検索窓を廃止する）体験
3. バーチャル品質ゲートと、採用／却下ログによる自己進化

本記事は特定ベンダーの実装教程ではなく、参照アーキテクチャと運用契約の下書きである。プロダクションでは権限・秘匿・バージョン管理が必須だが、まずは「人力で探すことをなくす」が成立するデータの流れを固定する。

## 1. 目指す体験（完成像）

設計者が CAD でフィレットRや公差を変更した瞬間、バックグラウンドで次が走る。

1. 変更差分（幾何特徴・寸法・公差）を抽出する。
2. 関連CAEケースがあればサロゲート／キャッシュから場の要約を付与する。
3. 多峰性共用埋め込みで類似の品証事例・製造リスクを候補化する。
4. 設計根拠知識グラフで根拠を展開し、BOP連動のコスト感度を添える。
5. CAD横に **非同期ポップアップ** で提示する（検索窓は使わない）。

提示例（イメージ）：

> 現在のR形状と公差設定は、過去に品証ゲートで却下された事例A（割れリスク）と類似度91%。工場の〇〇切削機での加工コストが20%高騰する予測（製造BOP連動）。推奨：Rを0.5大きくすると品証パス見込み上昇＆コスト15%削減。根拠：FMEA-… / DR-… / 工程-…

設計者は採用／却下／修正をログに残す。その選択が次の学習とゲート更新の入力になる。

## 2. 論点1：非同期データ統合パイプライン

### 2.1 ソース系

| ドメイン | ソース例 | 抽出物 |
| :--- | :--- | :--- |
| 設計 | CAD/PLM | EBOM、形状特徴、公差、バージョン |
| CAE | SPDM | ケース、境界条件、場の要約、合否 |
| 品証 | FMEA/不具合DB/DR | 故障モード、指摘、ゲート結果 |
| 製造 | MES/IIoT/MOM | 工程実績、加工ログ要約、歩留まり、コストドライバ |

### 2.2 パイプラインの原則

* **同期UIに同期ETLを繋がない**。CAD操作のレイテンシを守るため、重いベクトル化・グラフ更新は非同期ジョブとする。
* **生データと意味データの分離**。オブジェクトストレージ上の成果物と、グラフ／ベクトルストア上の契約データを分ける（シーズン4の検証レイヤと同型）。
* **対応写像 $m$ のバージョン管理**。EBOM–MBOM マッチング結果は Bridge としてリリースし、壊れた対応は品質ゲートで落とす。

```text
CAD/PLM ─┐
SPDM ────┼─→ Ingest (ELT) ─→ Feature/Graph Builders ─┬─→ Graph DB (Rationale)
FMEA/DR ─┤                                            ├─→ Vector Index（多峰性共用埋め込み）
MES/IIoT─┘                                            └─→ Cost/Risk Surrogates
                              ↑
                         非同期ワーカー
                              ↓
                    CAD Add-in ← Event Bus ← 推論API（低レイテンシ経路はキャッシュ優先）
```

### 2.3 低レイテンシ経路

操作連動で毎回フルCAEやフル対照推論を回さない。

* 特徴ハッシュ／幾何シグネチャでキャッシュヒットを優先する。
* 変更が局所なら局所近傍検索に限定する。
* 外れ値のみ非同期で精密再計算し、後からポップアップを更新する（楽観的提示＋訂正）。

## 3. 論点2：CAD連動プッシュ型UX

### 3.1 「検索させる」設計の廃止

キーワード検索は、設計者がリスク語彙を知っている前提になる。シフトレフトの本体は **コンテキスト連動のレコメンド** である。

UX原則：

* 割込みはするが、モーダルで作業を止めない（非同期ポップアップ／サイドパネル）。
* 類似度だけでなく、根拠リンク（FMEA・DR・工程）を必ず併記する。
* コスト・品質・納期（QCD）を同じカードに並べ、トレードオフを隠さない。
* 「採用」「却下」「後で」を明示し、沈黙を学習信号にしない。

### 3.2 役割別の見え方

* **設計**：形状変更の瞬間にリスクとコスト感度。
* **品証**：バーチャルゲートのキュー、未接地の類似候補レビュー。
* **製造**：上流で弾かれた無理設計の減少、BOP前提の可視化。

三者とも「自分の画面の問題が減る」ことが導入動機になる。DXスローガンより、手戻り件数とゲート再試行回数のKPIの方が効く。

## 4. 論点3：バーチャル品質ゲートと自己進化

### 4.1 FMEAの自動更新（人間は承認者）

新しい設計変更と、その後の実ゲート／試作結果をグラフへ接続する。

* 自動提案：新規辺・新規リスクノード・類似クラスタへの所属。
* 人間承認：品証が契約としてマージ（シーズン4の品質ゲート思想）。
* 拒否も資産：却下理由をテキスト＋リンクで残し、次の負例／制約にする。

### 4.2 フィードバックループ（RLHF的運用）

厳密なRLHFである必要はない。まずは次で足りる。

1. 提示カードへの採用／却下／修正。
2. 事後の実ゲート結果との突合（予測と現実のギャップ）。
3. ギャップが大きい領域の再学習・ルール追加・対応写像の見直し。

「システムが自己進化する」とは、ブラックボックスが勝手に賢くなることではなく、**グラフ契約とサロゲートがバージョンとして改善される運用エコシステム**を指す。

### 4.3 安全とガバナンス（下書きで固定したい制約）

* 類似度91%は決定ではない。決定権は設計変更プロセスと品証契約に残す。
* 社外秘の不具合票は権限付きインデックスに閉じる。
* 監査ログ：誰がどの根拠を見て採用したかを残す（説明責任）。

## 5. 参照実装への段階導入（現実的ロードマップ）

一気に多峰性共用埋め込みまで行かない。

| 段階 | 内容 | 価値 |
| :---: | :--- | :--- |
| 0 | EBOM–MBOM 対応の手動／半自動 Bridge と Graph Contract | 逆流の器を作る |
| 1 | FMEA/DR の構造化取り込みと、形状特徴IDへのリンク | 品証ハブの復活 |
| 2 | CAD差分イベント → ルール＋従来類似検索のプッシュ通知 | 人力で探すことの削減 |
| 3 | CAE要約・コストサロゲートの接続 | 感度カード |
| 4 | 共用埋め込みと継続学習 | 候補精度の向上 |

シーズン2の論理フェデレーション実装（部門グラフ＋Contract）は段階0–1の土台になる。シーズン5は、その上に **品証ハブとCAD時間軸のUX** を載せる拡張と位置づけられる。

## 6. シーズン5のまとめ

| 部 | 主張 |
| :--- | :--- |
| 第1部 | 三者の分断は観点差・ゲート化QA・マルチモーダルの壁という構造問題である |
| 第2部 | グラフ（因果）・埋め込み（類似）・最適化（感度）で同一フレームワークに載せる |
| 第3部 | 非同期統合＋CADプッシュ＋バーチャルゲートで人力で探すことをなくし、三者の知見を設計時点で使えるようにする |

設計には根拠と製造都合が早期に見え、品証には生きたFMEAが回り、製造には無理設計が減る——それが本三部作が目指す、マルチモーダル知見統合の実務像です。原価と品質のジレンマを小さくすることも、その効果の一例です。
