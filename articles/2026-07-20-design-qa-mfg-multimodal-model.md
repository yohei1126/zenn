## 概要

第1部では、設計・品証・製造の知見が繋がらない構造——EBOM/MBOMのトポロジー差、Gate化したQA、マルチモーダルな「探せ」運用——を問題化した。第2部では、設計の「意図」、品証の「ルール・実績」、製造の「現実」を、同一の情報科学的フレームワーク上で表現・紐付ける理論を置く。

本記事は万能の数式カタログではない。実装（第3部）が参照できるよう、次の三層に分解する。

1. **構造層**：因果をトリプルで固定する Design Rationale Graph と、EBOM–MBOM のトポロジー変換
2. **表現層**：幾何・CAE・テキストを共通潜在空間へ閉じる Joint Multimodal Embedding
3. **意思決定層**：仕様・品証制約の下でコストを扱う多目的最適化と感度

シーズン2の Graph Contract / Bridge Keys、シーズン4の「契約としての検証」は、ここでも前提になる。埋め込み類似度だけで合否を決めるのではなく、**辿れる根拠（グラフ）と、引ける類似（埋め込み）を役割分担する**。

## 1. 全体像：三層モデル

```text
[仕様 Req] → [CAE/SPDM] → [CAD/EBOM] → [FMEA/品証リスク] → [MBOM/BOP/MOM]
                │                │              │                  │
                └──── Design Rationale Graph（構造・因果）──────────┘
                                   │
                    Joint Embedding ℝ^d（幾何×場×言語の類似）
                                   │
                    多目的最適化（C(x), g(x), h(x)）と感度 ∇C
```

* グラフは「なぜその関係か」を説明し、監査可能にする。
* 埋め込みは「似た過去」を高速に候補化する。
* 最適化は「候補をどう選ぶか」をコスト・品質の言葉で定式化する。

---

## 2. 論点1：設計根拠ナレッジグラフ（Design Rationale Graph）

### 2.1 因果チェーンをトリプルで固定する

設計根拠を、少なくとも次の因果に分解して知識グラフ化する。

| 主語 (S) | 関係 (R) の例 | 目的語 (O) |
| :--- | :--- | :--- |
| 仕様 Requirement | constrains | CAE 解析ケース |
| CAE 結果 / 判定 | justifies | CAD 形状特徴・公差 |
| 形状特徴 | induces_risk | FMEA 故障モード |
| 故障モード | mitigated_by | 工程・設備・検査（BOP/MOM） |
| EBOM ノード | corresponds_to | MBOM / 工程ノード |

形式的にはトリプル $(S, R, O)$ の集合 $G=(V,E)$ とする。重要なのはオントロジー語彙の網羅ではなく、**エージェントやUIが「根拠を辿れる」最小の契約**であることだ（シーズン4の Contract 視点と同型）。

### 2.2 EBOM–MBOM の動的トポロジー変換

観点差を「マスタを無理に同一ツリーにする」ではなく、**対応写像**として扱う。

* 木として近似できる部分：Tree Edit Distance（挿入・削除・置換コスト）で構造差を測る。
* 一般の工程グラフ：Graph Matching / 部分グラフ同型の緩和（コスト付き割当）で対応候補を出す。

得られた対応 $m: V_{\mathrm{EBOM}} \rightharpoonup V_{\mathrm{MBOM}}$ を Graph Contract 上の Bridge として版管理する。製造側の歩留まりイベントは $m$ を経由して設計特徴へ逆流できる。対応が無い領域は「未接続リスク」として品証ハブの監視対象になる。

### 2.3 品証ノードをハブに置く

FMEA 項目・DR 指摘・試作合否を、単なる文書ノードではなく **設計特徴と工程の両方に辺を持つハブ** にする。Gate 記録も「合否フラグ」だけでなく、却下理由・類似形状・推奨緩和策へのリンクを残す。これが第3部のバーチャル品質Gateの理論的芯になる。

## 3. 論点2：多峰性共用埋め込み（Joint Multimodal Embedding）

### 3.1 共通潜在空間への投影

異種データを、対照学習などで共通の潜在空間 $\mathbb{R}^d$ に写す。

| モダリティ | エンコーダの例（研究方向のラベル） | 入力 |
| :--- | :--- | :--- |
| 形状 | PointNet 系 / メッシュ GNN | 点群・メッシュ・特徴ヒストグラム |
| CAE 場 | FNO / MeshGraphNets 系 | 境界条件＋場（応力・温度など） |
| テキスト | LLM / 文埋め込み | FMEA、不具合、DR 指摘 |
| （拡張）時系列 | 時系列エンコーダ | 加工ログ要約・異常スコア |

対照学習の直感は、「同じ案件・同じ故障ストーリーに属する (形状, CAE, テキスト) は近く、無関係は遠く」である。学習後、クエリ $q$（例：現在のR形状＋公差＋代表CAE条件）に対し、品証事例・製造リスク事例をコサイン類似度などで同時に引ける。

### 3.2 グラフと埋め込みの役割分担

埋め込みは候補生成に強いが、説明責任は弱い。運用上の原則は次とする。

1. 埋め込みで Top-k の類似トラブル・類似工程リスクを取る。
2. Design Rationale Graph で、その候補がどの仕様・どの工程・どの過去Gateに繋がるかを展開する。
3. 展開できない候補は「類似だが未検証」としてUI上で区別する（シーズン4の Grounding と同趣旨）。

「形状＋CAE条件 → 過去の品証却下事例＋加工コスト感度」を同時に返す、という体験は、この二段構えがあって初めて信頼可能になる。

### 3.3 数理的注意（下書き時点の境界）

* 産業データはペアが少なく、対照学習の負例設計が難しい。
* CAE 場の解像度・正規化がドメインシフトを起こす。
* テキスト側の社内スラング・帳票ゆらぎが埋め込み品質を支配する。

第3部では、まずグラフ対応とルール／類似検索のハイブリッドから始め、共用埋め込みを段階導入する現実解を採る。

## 4. 論点3：コスト・品質・性能の多目的最適化と感度

### 4.1 定式化の骨格

設計変数を $x$（形状パラメータ、公差、材料選択肢などの符号化）とする。

* 仕様・性能制約：$g(x) \le 0$
* 品証・安全率・公差制約：$h(x) \le 0$
* 目的：製造コスト $C(x)$ の最小化（またはコストとリスクの加重和）

$$
\min_x \; C(x) \quad \text{s.t.} \quad g(x) \le 0,\; h(x) \le 0
$$

実務では $C(x)$ も $h(x)$ も閉形式ではない。BOP連動のコストモデル、歩留まり予測、過去Gateの類似度ベースリスクを **サロゲート** として置く。

### 4.2 感度 $\nabla C(x)$ と説明

ラグランジュ緩和やサロゲートの自動微分／差分近似で、「このRを $0.5$ 大きくしたときのコスト変化・品証パス確率変化」を提示する。UIに出すのは最適解そのものより、**局所感度と根拠リンク**の方が設計者に刺さる（第3部のプッシュ型UXの中身）。

### 4.3 「ジレンマを打ち破る」の意味

トレードオフ曲面を消す魔法ではない。品証知見を $h(x)$ 側に早期に埋め込み、実行可能領域の内側で $C(x)$ を下げる——つまり **後工程Gateで初めて見える非実行可能点を、設計時点で除外する** ことが本連載における「打ち破り」の定義である。

## 6. 第2部の結論と第3部への橋渡し

第2部の主張を要約する。

1. Design Rationale Graph で Req→CAE→CAD→FMEA→工程の因果を辿れるようにする。
2. EBOM–MBOM は同一化せず、トポロジー変換・マッチングで対応を契約化する。
3. Joint Embedding は類似候補の生成器、グラフは説明と検証の器として分ける。
4. 多目的最適化は「品質制約下のコスト最小化＋感度提示」として、シフトレフトUIに供給する。

第3部では、この理論を **非同期データパイプライン、CAD連動プッシュUX、バーチャル品質Gateと自己進化** として実装像に落とす。
